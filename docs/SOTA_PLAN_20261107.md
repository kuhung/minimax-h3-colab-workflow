## 项目差距与成本

现有链路是文本驱动的音视频批处理。节点叫 `MiniMaxH3ImageToVideo`，不等于已接入用户参考图。`format_h3_prompt` 已支持分镜和时间字符串，后续补时间范围校验，不再造提示词组装器。渲染器已有按连接寻找条件节点的逻辑，但仍遍历并修改所有同类 I2V 节点；引入多分支后需改成从输出端追踪实际执行路径。

`validate_and_adapt_workflow` 在获取不到 `/object_info` 时直接放行，也会删除未知字段。参考图、音轨绑定、提示词、宽高属于语义必需输入，不能被静默删除。应在适配后验证最终提交图，取不到契约则阻止新模式提交，并保存错误记录。

统一使用 **1.94 CU/h、约 0.089 CU/稳态镜**，作为仓库已有 L4 记录口径：960×544、124 帧、24fps、Turbo 8 步、BasicGuider。按 165.4 秒计算：`1.94 × 165.4 / 3600 ≈ 0.0891 CU`。三镜 574.6 秒对应约 0.3097 CU；历史记录写 0.309 CU，应保留并注明显示精度/计时边界尚待复核，不能把二者描述为精确相等。三镜批次均摊约 0.103 CU/镜，含首镜开销，不能混用稳态值。

阶段一历史原文保留；其 0.087 CU 自本方案起停用。阶段二统一 README、研究总结与路线图的现行数字，删除“稳定月产量”“4步必为80秒”“纯本地免费无成本”等保证。启动、下载、空闲、失败与重试均纳入会话账单；每次记录 CU 起止值，费率以当前 Colab 面板为准。GPU 24GB 标称显存不等于可用显存，也不等于权重文件能同时常驻。

## 最佳实践取舍

下表覆盖简报七部分。文件名为拟交付路径；未标已有的内容均待实施。

| 实践 | 决策与理由 | 具体改动 |
|---|---|---|
| API Lite/Highspeed 探路、完整版定稿 | 不采用端点；采用本地分层思路。生产保持 8 步，4 步为候选快筛，不能提前承诺速度或声音质量 | 阶段四在 `configs/experiments/` 配成对 4/8 步实验；复用 `download_models.py` 已有步数参数，检查 runner、LoRA 与 scheduler 一致性 |
| 2K、Regenerate-2K | 明确放弃，超出本地范围 | 能力表仅写实测本地规格，不加超分替代支线 |
| Context-IR、Hub 画布 | 不调用托管编排，不安装依赖 Hub 的八种工作流；本地提示词指南可吸收，不能宣传等价编排质量 | `PROMPT_RECIPES.md` 引用官方 `base-en.txt` / `ref-en.txt`，由人工或已有 Agent 产出本地 JSON，无新 API 密钥 |
| Ref2VA 配额与绑定 | 采纳为保守输入门禁，仅适用于 Ref2VA；图片≤9、视频≤3、音频≤3、合计≤12，视频/音频各累计≤15秒；片段2–15秒，拒绝纯音频输入 | 阶段三 C 新增 `scripts/validate_inputs.py`，显式引用到真实媒体 ID；上游当前契约更严格时取更严格值 |
| 毫秒时间线、四段式提示词 | 采纳意图表达，不保证毫秒级生成控制；最终切点由剪辑实现 | 扩展已有 `format_h3_prompt`：校验时间递增且不越界；`PROMPT_RECIPES.md` 加主体场景、定时动作、镜头、光声模板 |
| 静态资产先行 | 采纳；固定角色与服装后生成分镜，有利于减少漂移，效果仍需案例验收 | `configs/assets.example.json` 记录角色/场景 ID、授权来源与图像校验和；接收用户图片或已有本地工具生成图，不新增 T2I 服务 |
| I2V 提示词减法 | 采纳，图片承载外观，文本描述运动与变化，附一致性限制 | 首帧示例只写动作、镜头速度、环境变化与不新增人物等约束；与长外观提示词成对比较 |
| 首帧、尾帧、首尾帧 | 分步采用 FL2VA 官方模板；多张身份参考属于另一条 Ref2VA 链路 | `workflows/h3_i2v_production.json` 与 `h3_flf2v_production.json` 从官方模板导出 API 图；不手搭新算法、不覆盖 T2V 模板 |
| JSON 分镜 | 采纳，区分叙事字段、生成时长与剪辑时长 | 扩展配置为 shot_id、mode、duration_sec、scene、character、action、dialogue、subtitle、seed、asset_ids；字幕每行≤15汉字，时长换算后记录实际帧数 |
| 2–5秒一镜、60–90秒约10–14镜 | 作为创作建议调整使用。镜数与总时长需算术自洽；生成长度受当前节点限制，短镜可先生成后裁剪 | 校验分镜时长总和与目标时长；首轮沿用约5秒生成规格，不直接承诺所有2秒输入均可执行 |
| 按镜头路由 | 采纳本地规则：无参考 B-roll→T2VA；外观锚定→I2V；起止控制→FLF2V；多主体参考→Ref2VA（通过实测后） | `batch_runner.py` 按显式 mode 选模板；不支持的模式返回错误，不静默退回 T2V |
| 大动作转可灵 | 不采用外部模型服务及其密钥；改简动作、拆镜或使用现有素材剪辑 | 在提示词指南写出本地失败处理规则，保留未达标标签 |
| 尾帧续接 | 在阶段三 B 采用；只能辅助画面连接，不能保证运动和声音连续 | 通过现成 FFmpeg 无损 PNG 导出末帧，记录父镜头 ID；检查新片段首帧、接缝亮度与声音 |
| 自然语言局部返工 | 不把闭源定点改片当现有能力；先按镜重生成，复用其余合格镜头 | 按 shot_id/seed 保存配置与版本；局部重绘放入阶段四可选 ControlNet 实验 |
| 对白/环境音/BGM 三轨 | 采用后期分轨思路，当前优先原生环境音；对口型不列为已支持 | `docs/POSTPRODUCTION.md` 写 FFmpeg 分轨、字幕与混音方案；无声或声音不合格镜头明确标记；本地配音/对口型另行验证后再入主线 |
| 模型三模块及架构细节 | 采纳边界说明；不因架构描述修改已跑通运行时 | 能力表区分开源生成与闭源编排/2K，不把系统总能力套在量化本地模板上 |
| 三代模型、比例与文字规则 | 采纳提示词模式分离；H3 自然语言、参考媒体绑定分别处理 | 文档注明 H3，不复用老端点中括号运镜指令；字幕/Logo优先后期叠加，生成文字逐帧核对且英文署名仅一次，无多余中文/乱码 |
| 单变量迭代与跨模型迁移 | 采纳；模型、种子、时长、尺寸固定，每轮只改一个变量 | `docs/benchmarks/` 保存对照 manifest、输出位置和人工评价；迁移提示词补速度、目标、时间和声音，不盲用旧语法 |
| 现成教程、环境与硬件配置 | 采纳，保留现有 L4 门禁、看门狗、Drive 缓存及原生封装 | 官方模板→API图→现有 runner 适配；每模式记录节点/环境/权重版本；不迁移整套部署框架 |
| pruned量化、NVFP4编码器、INT8 VAE | 保留当前已跑通组合与 fp16 回退，不一次升级全套 | `download_models.py` 后续补模式权重清单、revision/hash；真实峰值显存、主机内存、加载时间分别记账 |
| GGUF/Unsloth、W4A8、vLLM-Omni、SGLang及其他硬件适配 | 暂不采用，切换后端/算子会扩展维护与验收范围，不能解决当前传图缺口 | 保留来源线索于 `REFERENCES.md`，L4现有路线受阻时才评估；GGUF的CFG与CPU卸载规则不套用当前Comfy运行参数 |
| FastH3 Trim、FastH3/V2、DMAD | 延后独立对照，不能把各版本模式支持混为一谈 | 阶段四先核对各checkpoint支持模式及原生节点，再决定是否试验；仅T2V版本不可用于I2V/Ref2VA |
| Turbo、TE-Speed、PowerLoraStack | 保留现有Turbo 8步；缓存与叠加插件暂不入生产。原生单LoRA足够支撑当前目标 | 阶段四每次只引入一项；需自定义插件则留实验模式，不能继续宣称该模式零第三方插件 |
| INT8 VAE加速与黑片风险 | 采用内容检查和fp16回退；不由版本号直接保证性能 | 对成片检查非全黑、帧数、可解码与试听；失败时留失败账单并回退已知组合，不覆盖原结果 |
| Fun-Controlnet-Union | 延后，先完成基础参考图闭环 | 有明确姿态/局部重绘失败样例后，复用官方模板做小范围对照 |
| Motion-Context与ToneCompensate | 延后；先验证简单尾帧续接是否足够 | 阶段四有连续镜头暗化或运动断裂证据再评估；保留 BT.709 元数据，避免额外加载器造成色偏 |
| Ref2VA 24fps、音画分接 | 采用并验证实际模板契约，禁靠文件顺序猜映射 | 预处理保留原件与转码件；视频画面/音轨分开绑定，附带音轨优先编号，记录引用表；含音视频连接 video VAE 与 audio VAE，独立音频仅 audio VAE |

## 运行与验收约定

生产模板只读，实验输出进入 `workflows/experiments/` 与独立产物目录；冒烟前后核对生产模板 hash。基于连接定位实际条件节点，修改后与契约裁剪后均验证提示词、宽高、帧数、mode、媒体绑定及LoRA步数，缺失即报错。干跑覆盖重排节点 ID、多个同类节点、错误图片路径、缺失 `/object_info`、未知必需字段、越界时间戳与不合法配额，确认均不提交任务。

GPU 冒烟沿用约5秒、16:9、固定种子，先检查能加载和完整输出，再评质量。每次记录：GPU/CUDA/ComfyUI commit、权重 revision、模板 hash、种子、请求与实际尺寸/帧数、首镜/热跑耗时、峰值显存/主机内存、面板CU起止、失败原因、音画产物。新模式不套用T2V成本。先单镜，再三镜小批，发现OOM或黑片立即终止，不自动无限重试，保留现有自动关机保护。

叙事案例至少三镜，公开输入、配置和全部输出选择依据。逐镜核对角色五官、服装、道具/Logo、运动完成度、接缝、噪声与声画关系。任何明显身份变化或黑片均不能算通过；如失败，保留对照并返工，不用抽样截图替代完整观看。推广阶段不以Star或曝光作为技术验收。
