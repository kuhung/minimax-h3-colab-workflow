## 三、 篇章大纲与内容架构

### 第一篇：技术选型：海螺 3.0 处于什么水平？核心指标与横评横比

- **定位文件**：`docs/articles/01-introduction-and-principles.md`
- **核心主旨**：站在行业高度审视 2026 年的主流视频模型，确立评判 AI 视频生成的核心技术指标，客观看清海螺 3.0 相比行业第一梯队（如 Seedance 2.0/2.5 等 C 档主力）的长板与差距，建立全局选型框架。
- **核心章节**：
  1. **评判 AI 视频生成模型的核心技术维度**
     - 衡量一个视频生成模型，行业通常看五大核心技术指标：
       - **时序与上下文一致性**：多帧运动中人脸、服装、结构是否发生扭曲或漂移；
       - **多模态参考输入上限**：支持同时喂入多少张图、多少段音视频来共同约束生成；
       - **音画同频与原生生成**：是画面无声靠后期硬贴，还是底层联合扩散出原生 32kHz 立体声；
       - **复杂物理模拟与运动幅度**：大范围肢体冲突、流体与动力学规律的遵循程度；
       - **开源生态与推理成本**：是否支持消费级显卡本地量化部署，单镜推理延迟与算力开销。
  2. **海螺 3.0 的技术定位与横向对标**
     - **横向对标 C 档（如 Seedance 2.0 / 2.5）**：诚实看到差距所在——在复杂长时序叙事理解、超大幅度肢体对抗以及超大规模编排生态上，开源的 H3-Base 相比顶级托管闭源大模型仍有一定代差；
     - **海螺 3.0 的突出长板**：
       - 率先支持最高 12 个多模态参考文件（≤9 张图、≤3 段视频、≤3 段音频）的 Ref2VA 上下文控制；
       - 原生 32kHz 高保真立体声音画同频生成，省去了后期音效拼凑的断层；
       - 开放 768p 33B 单流 DiT 架构主干权重，为本地化与私有化生产提供了坚实底座。
  3. **不同主流模型的场景分工矩阵**
     - 可灵（Kling）：单镜头超大物理动作幅度与长视频延长；
     - Google Veo 3.1 / OpenAI Sora 2：照片级声画与 16–20 秒长时序创意镜头；
     - 通义万相 Wan 2.1：开源生态中优异的首尾帧（FLF2V）控制流；
     - MiniMax H3：商品外观锚定、多参考素材绑定、原生立体声环境音出片。
  4. **文末专属**：
     - 系列导航；
     - 原文对照与参考文献。

### 第二篇：流程落地：我们跑通的基准工作流，与关键参数的决定性影响

- **定位文件**：`docs/articles/02-timeline-prompting.md`
- **核心主旨**：从高屋建瓴的角度介绍我们目前在本地实际跑通的标准生产流水线，不堆砌无关紧要的代码琐碎，而是深入剖析**关键工程决策与核心参数对最终生成结果的决定性影响**。
- **核心章节**：
  1. **基准流水线的核心架构设计**
     - 为什么选择单流 Transformer + 8 步 Turbo 采样方案；
     - 为什么坚持 ComfyUI 官方原生内置节点打包 MP4，杜绝第三方插件的黑盒依赖；
     - 硬件守门与资源管控：GPU 算力门禁与看门狗自动关机的系统性设计。
  2. **核心参数对最终视频结果的决定性影响**
     - **无分类器引导（BasicGuider，CFG=1.0）的决定性意义**：
       - 传统双路 CFG(3.0) 强制每步前向计算 2 次（8 步共 16 次），自注意力计算呈非线性激增且容易引发画面过饱和与伪影；
       - 单路无 CFG（1.0）精确执行 8 次前向计算，算力消耗直接降低 74%，且色彩还原更加纯净自然。
     - **分辨率选择对显存与计算复杂度的深层影响**：
       - 为什么选择 960×544 作为黄金规格：相比 1344×768（像素暴增 97.6%），544p 避免了 DiT 自注意力计算的指数级爆炸，将整卡峰值显存精准控制在 21.77 GB，避开了 OOM，稳态热跑压在 165 秒/镜（0.089 CU）。
     - **采样步数与动态涂抹（Motion Smear）的平衡**：
       - 压到 4 步易出现动态细节涂抹，8 步 Turbo 能够在极短时间内兼顾物理质感与运动清晰度。
  3. **实际生产成果展示（上海街景系列实测）**
     - 结合跑通的弄堂生煎（微距油煎与环境声景）、法租界梧桐（慢推运镜与电车低鸣）、外滩雨夜（反光地面积水与轮船汽笛），展示这一套工程参数在真实世界质感上的沉淀结果。
  4. **文末专属**：
     - 系列导航；
     - 原文对照与参考文献。

### 第三篇：场景探索：从文生到首尾帧与视频生视频，全模态控制流的打通

- **核心章节**：
  1. **AI 视频生成的全场景输入图谱与单目的脚本设计**
     - 为什么拒绝大杂烩脚本：单一实验目的、原子化排障、极简上手；
     - 首帧图生视频（I2V，`v3.1`）：锁定商品 Logo、人脸外观与固定构图；
     - 首尾帧视频（FLF2V，`v3.2`）：精准约束动作起止边界，消除生硬溶解的渐变 Bug；
     - 全模态参考 / 视频生视频（Ref2VA，`v3.3`）：运镜轨迹迁移、角色动作复刻与双音轨协同。
  2. **各类输入模式的技术机制与实现逻辑**

     - 首尾帧如何在潜在空间两端建立条件约束，实现平滑形变与过渡；
     - 视频生视频与多参考如何通过 Cross-Attention 提取运动特征与声音节拍。
  3. **可替换场景模板库与即换即跑实践（读者获得感）**

     - **空间与形态演变**：首尾帧平滑转场模板（`flf2v_morph_transition.json`），两端透视对齐；
     - **动态运镜与动作迁移**：全参考复刻模板（`ref2va_motion_transfer.json`），24fps 动作复刻与双轨音频分流；

### 第四篇：工业交付：面向垂直领域的端到端 SOTA 制作流水线

- **定位文件**：`docs/articles/04-architecture-and-local-deployment.md`
- **核心主旨**：从单镜头的原子控制跨越到多镜头的系统工程。面向专业团队与垂直创作者，呈现一套真正能够工业化交付的端到端“搜塔”（SOTA）流水线标准，全面攻克长程连贯性难题。
- **核心章节**：
  1. **工业化流水线的第一原则：长程连贯性与工序解耦**
     - 为什么单靠抽卡无法交付工业作品：必须建立跨镜头的系统工程约束。
     - **角色一致性“三级保障机制”**：
       - 一级：结构化固定身份描述块与负面身份规则；
       - 二级：分镜静态关键帧定妆照资产锁定；
       - 三级：动态生成期通过 Ref2VA 绑定定妆照与动作参考。
     - **长镜头无损衔接与防“渐变 Bug”**：
       - 尾帧无损抓取作为下一镜首帧接续，遵循首尾帧动量守恒，防镜头断裂。
  2. **标准六步 SOTA 制作流水线（`v4.0` 脚本落地）**
     - **步骤一：剧本结构化为 JSON 分镜**（单镜 2–5 秒黄金规格，10–14 镜标准节奏，字幕每行 ≤15 汉字）；
     - **步骤二：静态资产与分镜关键帧锁定**（多角度定妆照 + I2I 派生分镜静帧）；
     - **步骤三：动态路由至专长引擎**（空镜走 T2V、商品走 I2V、场景过渡走首尾帧、剧情走 Ref2VA）；
     - **步骤四：长镜头尾帧接续与定点返工**（尾帧无损接续，局部瑕疵单镜重构）；
     - **步骤五 & 六：三层声音分轨与后期精修**（对白、环境音、BGM 独立分轨与唇形同步）。
  3. **24G 显存环境下的工业化工程保障**
     - 多镜头连续生成的亮度与色调防暗补偿（引入 `ToneCompensate` 锁定 BT.709）；
     - 权重分层存放与量化主干配置；
     - 交付标准与团队协作流。
  4. **文末专属**：
     - 原文对照与参考文献。
