## 实测耗时差异说明

对比 [`v1_0_minimax_h3_l4_benchmark_webp.ipynb`](./v1_0_minimax_h3_l4_benchmark_webp.ipynb) 与 [`v2_0_minimax_h3_l4_production_mp4.ipynb`](./v2_0_minimax_h3_l4_production_mp4.ipynb) 的实测日志，可以观察到以下计算特征：

### 1. v1.0 同批次 315s 与 875s 的差异来源
在 [`v1_0_minimax_h3_l4_benchmark_webp.ipynb`](./v1_0_minimax_h3_l4_benchmark_webp.ipynb) 日志中：
- **冒烟测试（冷启动）**：`960×544`，耗时 `393.78 秒`（含权重首次载入显存开销）。
- **分镜 1（咖啡机，热跑）**：`960×544`，耗时 `315.83 秒`。
- **分镜 2（数据中心，热跑）**：`1344×768`，耗时 `875.35 秒`（约 14.6 分钟）。
- **分镜 3（机械键盘，热跑）**：`1344×768`，耗时 `874.08 秒`（约 14.6 分钟）。

差异主要来自三方面：
1. **像素规模**：`1344×768`（103.2 万像素）相对 `960×544`（52.2 万像素）增加 **97.6%**。
2. **DiT 注意力复杂度**：单流 DiT 的时空自注意力序列长度随像素数量同步拉长，计算量呈非线性上升。
3. **双路 CFG=3.0 开销**：`v1.0` 每步需分别前向一次正向与负向条件（8 步共 16 次 DiT 前向传播）。
4. **同规格一致性**：相同分辨率下分镜 2（`875.35s`）与分镜 3（`874.08s`）差异小于 `1.3 秒`（`< 0.15%`），耗时变化主要由画面分辨率规格决定。

### 2. 双路 CFG(3.0) + 768p 的超时风险
若在 `1344×768` 高分辨率下叠加双路 CFG=3.0 的 16 次前向与 `VAEDecodeAudio`，单镜耗时显著高于稳态预算区间，容易触及 Colab 看门狗超时保护。仓库中的 [`v1.5_minimax_h3_l4_legacy_mp4.ipynb`](./v1.5_minimax_h3_l4_legacy_mp4.ipynb) 仅作历史双路模板归档，未保留云端运行输出。

### 3. v2.0 实测记录（960×544，124 帧 @ 24fps）
在 [`v2_0_minimax_h3_l4_production_mp4.ipynb`](./v2_0_minimax_h3_l4_production_mp4.ipynb) 中：

1. **单镜耗时**：
   - **分镜 1（冷启动）**：`243.5 秒`（2.42 MB MP4，含首次将 DiT 与 AudioVAE 加载入显存）。
   - **分镜 2（热跑稳态）**：`165.3 秒`（0.63 MB MP4，含 32kHz 立体声音轨）。
   - **分镜 3（热跑稳态）**：`165.5 秒`（1.23 MB MP4，含 32kHz 立体声音轨）。
   - **3 镜合计耗时**：`574.6 秒`（`9.58 分钟`）；稳态平均 `165.4 秒 / 镜`，相比 `v1.0` 同分辨率（`315.8s`）提速 **47.6%** 并附带立体声音轨，也显著低于 `v1.0` 在 `1344×768` 下的 `874~875 秒`。
2. **CU 消耗与显存口径**：
   - 3 镜批次实测消耗约 `0.309 CU`；按 `1.94 CU/h` 折算，稳态单镜约 `0.089 CU`（三镜均摊约 `0.103 CU/镜`）。
   - 若仅按稳态 `0.089 CU/镜` 估算，100 CU 理论约合 ~1,120 次稳态生成，但**未计入**冷启动、权重拉取、空闲与返工，**不构成月产量保证**；实际计费以 Google Colab 实时面板为准（Pay-As-You-Go `$9.99 / 100 CU`、Colab Pro `$9.99/月`、Colab Pro+ `$49.99/月`，核对日期：2026-11-12）。
   - 显存参考 `v1_0` 544p 冒烟测试：`nvidia-smi` 记录去噪稳态 `21.77 GB`、整卡峰值 `21.91 GB / 22.03 GB`（余量约 `0.12 GB`）。
3. **运行环境与加载机制**：
   - 实测实例提供 PyTorch `CUDA 13.0` (`cu130`)，直接启用 `int8_convrot` 内核。
   - Notebook 优先从 HuggingFace 直拉约 40GB 权重到本地 NVMe（实测 5 组核心文件共 `136.32 秒` 就绪并通过 safetensors 头部校验），避免直接通过 Google Drive FUSE 读取大文件引发的吞吐阻塞。

## 版本命名与维护约定

1. **统一语义版本前缀**：保留 `v1.*`、`v2.*`、`v3.*`、`v4.*` 编号；下划线版本为存证日志，小数点版本为干净模板。Colab 运行时请优先选用带清晰版本号的模板（如 `v2.0_minimax_h3_l4_production_mp4.ipynb`）。
2. **脚本生成模板同步**：`v1.0`/`v2.0`/`v3.x` 模板由 `scripts/generate_notebook.py`、`scripts/build_shanghai_notebook.py`、`scripts/build_v3_notebooks.py` 程序化生成并做 `ast.parse` 语法检查，避免只改本地 Notebook 而与生成脚本脱节。
3. **上传核对**：修改后重新上传 Colab 运行前，核对第一行标题与版本标识是否与本地一致。
