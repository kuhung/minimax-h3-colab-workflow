## 🔍 深度复盘：实测耗时为什么会有 165s、315s 与 875s 的巨大差异？

在经过多轮 Google Colab 真实运行存证（实测文件 [`v1_0_...webp.ipynb`](./v1_0_minimax_h3_l4_benchmark_webp.ipynb) 与 [`v2_0_...mp4.ipynb`](./v2_0_minimax_h3_l4_production_mp4.ipynb)）后，我们完整还原了物理计算真相：

### 1. 为什么 v1.0 同一批次中，镜头 1 只要 315 秒，而镜头 2 和 3 暴涨到 875 秒？
在 [`v1_0_minimax_h3_l4_benchmark_webp.ipynb`](./v1_0_minimax_h3_l4_benchmark_webp.ipynb) 实测日志中：
- **冒烟测试（冷启动加载）**：960x544，耗时 `393.78 秒`（首次将 DiT 与 VAE 权重自内存载入 GPU 显存，产生 ~78 秒冷启开销）。
- **分镜 1（咖啡机，热跑）**：960x544，耗时 `315.83 秒`（稳态运行，与早期 306 秒基准一致，差异仅 3% 属正常租户波动）。
- **分镜 2（数据中心，热跑）**：1344x768，耗时 `875.35 秒`（约 14.6 分钟）。
- **分镜 3（机械键盘，热跑）**：1344x768，耗时 `874.08 秒`（约 14.6 分钟）。

**深究核心机理（分辨率与 DiT 计算复杂度）**：
1. **像素量近乎翻倍**：960x544 为 52.2 万像素，而 1344x768 为 103.2 万像素（**+97.6%**）。
2. **DiT 注意力二次方膨胀**：DiT（Diffusion Transformer）的空间 Patch 序列长度随像素翻倍而翻倍，自注意力机制（Self-Attention）计算量呈超线性急剧攀升。
3. **v1.0 双路 CFG(3.0) 的双倍惩罚**：旧版架构每一步去噪必须做 Unconditional 和 Conditional 两次前向计算（8 步共 16 次 DiT 前向）。16 次前向传播 × 103 万像素，直接把单镜耗时推到了 875 秒！
4. **极致的物理稳定性**：在相同分辨率下，分镜 2（875.35s）与分镜 3（874.08s）的耗时差异**小于 1.3 秒（误差 < 0.15%）**，证明耗时差异并非由于“系统不稳定”，而是完全由**画面分辨率物理规格决定**。

---

### 2. 为什么 v1.5 会在 Colab 上遭遇 631s 超时中断？
在 `v1.5` 架构下，同时叠加了 1344x768 高分辨率、双路 CFG(3.0) 16 次前向、以及新增的 32kHz 音频解码（`VAEDecodeAudio`），整体计算负荷超过了脚本预设的心跳阈值，导致任务超时被看门狗中断。

### 3. v2.0 实测存证数据：如何实现 165 秒极速生产与音画同出？

在最新运行并完整保留 Colab 输出的实测存证文件 [`v2_0_minimax_h3_l4_production_mp4.ipynb`](./v2_0_minimax_h3_l4_production_mp4.ipynb) 中，核心性能指标如下：

1. **单镜头耗时表现（锁定 960x544 黄金规格, 124 帧 @ 24fps ≈ 5.17 秒）**：
   - **分镜 1（冷启动与权重搬运）**：`243.5 秒`（文件大小 2.42 MB，含首次加载 DiT 与音频 VAE 到显存的开销）。
   - **分镜 2（热跑稳态渲染）**：`165.3 秒`（2 分 45 秒，文件大小 0.63 MB，原生 32kHz 音画合成）。
   - **分镜 3（热跑稳态渲染）**：`165.5 秒`（2 分 45 秒，文件大小 1.23 MB，原生 32kHz 音画合成）。
   - **3 镜总渲染耗时**：**574.6 秒（仅 9.58 分钟）**！
   - **稳态平均耗时**：**165.4 秒 / 镜头**，相比 v1.0 的 315 秒不仅速度提升了 **47%**，而且额外获得了高品质的双声道立体声环境音！彻底终结了 1344x768 下 875 秒的漫长等待。
2. **算力单元消耗与生产成本（L4 官方实测费率 1.94 CU/h）**：
   - 3 个镜头批量生产总耗费：**0.309 CU**。
   - 稳态单镜生成成本：$$1.94 \times \frac{165.4}{3600} \approx \mathbf{0.089\ \text{CU / 镜头}}$$。
   - **1 个计算单元（CU）即可稳定输出 ~11.2 个带完整音频的高清短视频分镜！**
   - Google AI Pro（每月 100~300 CU）：每月可稳定产出 **1,120 ~ 3,360 镜头**。
   - Google AI Ultra（每月 500~1,500 CU）：每月可稳定产出 **5,600 ~ 16,800 镜头**。
3. **环境与权重加载突破**：
   - **CUDA 13.0 原生激活**：实测当前 Google Colab 分配的 L4 实例已提供 PyTorch CUDA 13.0 (`cu130`) 运行库，自动点亮 `int8_convrot` 原生硬件量化内核！
   - **HF 直连 NVMe 极速就绪**：首选直接拉取 HuggingFace 官方源至本地高速 NVMe，5 大核心权重（近 40GB）**仅耗时 136.32 秒（2.27 分钟）** 即可秒级就绪并通过 safetensors 头部双校验，彻底终结了从 Google Drive FUSE 软链接读取造成的显存饥饿等待！

## 🛠️ 文件管理规约与防混淆指南

为防止后续再次出现“盲目覆盖、线上跑的与本地想的不一致”：

1. **严格单一语义版本控制，杜绝无版本号混乱**：
   - 本目录仅保留具备明确语义版本的 `.ipynb` 文件（`v1.0_*`, `v1.5_*`, `v2.0_*`）。
   - 彻底删除早期无编号文件（`minimax_h3_l4_benchmark_run_results.ipynb`、`minimax_h3_l4_production.ipynb`、`test_shanghai_mp4_audio.ipynb` 等），消除命名歧义与覆盖混乱。
   - 在 Colab 中调试与运行任务，必须指认带明确版本前缀的文件（例如生产运行选 `v2.0_minimax_h3_l4_production_mp4.ipynb`）。
2. **禁止手动在 Notebook 内部随意硬编码改动**：
   - 生产 Notebook 均由 `scripts/generate_notebook.py` 和 `scripts/build_shanghai_notebook.py` 程序化生成。
   - 生成脚本会执行 `ast.parse` 静态分析与 node 拓扑校验，确保无未定义变量、无断链节点。
3. **线上 Colab 与本地严格对齐**：
   - 每次修改后，在 Colab 中请重新上传对应的版本文件，或检查第一行 Markdown 中的 `版本标识` 是否与本地一致。
